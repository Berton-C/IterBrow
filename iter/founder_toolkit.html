🚀 Founder Toolkit — OSS Inspiration Board

Curated 2026-09-14 · Purpose: projects that could extend Iter's capacity as a founder ally. Grouped by how they'd plug into Iter's architecture (browser + agent + tools + tiered memory).

1. Customer & Pipeline (CRM)

Twenty → GitHub

TypeScript · modern open-source CRM (Notion-style UI) · ~20k+ stars

Why for Iter: A CRM tab inside IterBrow means a founder's whole pipeline lives where their AI ally already operates. Iter could scan deals, draft follow-ups, spot stale opportunities, and enrich contacts from memory. Enhance: skip the app entirely — model the CRM as localStorage/JSON stations like the existing workbench, with Iter as the automation layer.

2. Workflow & Automation

N8N → GitHub

TypeScript · fair-code workflow automation · 60k+ stars

Why: Founders drown in glue work. Iter's tool-calling loop is already a workflow engine — borrow N8N's node/trigger concept for declarative startup chores: "when new signup → post to Slack → log to CRM." Iter enhancements could translate natural-language into trigger graphs and execute them via scheduled reminders + browser automation.

3. Backend & Data

Supabase → GitHub

Postgres + auth + realtime + storage · 70k+ stars

Why: Founders' #1 ask of a technical ally. Iter can't hold a database — but could act as the operator: scaffold schemas, write migrations, debug RLS policies, and even narrate API design, while Supabase does the heavy lifting.

4. Product Analytics

PostHog → GitHub

Product analytics, funnels, session replay, flags · 20k+ stars

Why: Iter's browser can open the founder's PostHog dashboard and read it back to them: funnel drop-offs, retention curves, anomalous traffic — turning a wall of charts into a spoken insight. Enhance: NAL-style evidence weighting on top of growth metrics fits Iter's reasoning substrate naturally.

5. Scheduling & Ops

Cal.com → GitHub

Open-source scheduling infrastructure · 30k+ stars

Why: A founder ally that can actually book meetings is a step change. Iter's reminder tool + browser automation could drive Cal.com's API to propose slots, book calls, and prepare briefing docs from meeting invite context stored in memory.

6. AI Copilots & Agents

Continue → GitHub

VS Code + JetBrains AI code assistant · 15k+ stars

Why: Iter already has the reprogramming.txt self-extension mechanism — Continue's IDE-integration patterns (context providers, slash commands, LLM config) are a great template for making Iter's capability-adding flow more founder-accessible ("add a Figma importer" becomes one command).

OpenHands (formerly OpenDevin) → GitHub

Autonomous software engineering agent · 40k+ stars

Why: The strongest architectural cousin: an agent with a browser + shell + editor sandbox. Iter already has shell + browser tools — OpenHands's event-stream architecture and task-planning loop could inspire richer multi-step founder tasks (e.g., "set up the whole launch repo end-to-end").

7. Notetaking & Knowledge

Affine → GitHub

Open-source Notion/Miro hybrid · local-first · 40k+ stars

Why: Iter's tiered-memory pyramid is already a knowledge system. Affine's local-first canvas + doc duality suggests a "founder second brain" tab — whiteboard + structured notes — that Iter can both render AND reason over (search, summarize, link to LTM memories).

8. Comms

Cal.com sibling: Chatwoot → GitHub

Open-source customer messaging (Intercom alternative) · 20k+ stars

Why: Founders answer the same customer questions repeatedly. Iter could draft replies, cluster tickets into themes, and — given its memory — notice when a customer's issue echoes an earlier one, cross-referencing past resolutions automatically.

9. Growth

Listmonk → GitHub

Newsletter + mailing manager · 15k+ stars

Why: Content is a founder's growth engine. Iter could draft launch emails, segment audiences, and use the tiered-memory pattern to remember what tone/subject lines worked across campaigns — an actual learning loop for copywriting.

Biggest architectural insight: Iter's unique edge vs all of these standalone tools is the memory + agency + browser in one. Any of these projects becomes dramatically more useful when a persistent agent can operate it, observe it over time, and remember what it learned — that's the enhancement multiplier.
