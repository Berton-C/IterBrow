# ADR-0013: Complete integrated build and isolated development

- Status: accepted direction; implementation in progress, not deployed
- Date: 2026-09-22 (America/Los_Angeles)
- Amends: ADR-0012 delivery sequence and Product Build Contract v1
- Authority: the user's explicit correction that swift means a complete working structure,
  retaining cognitive fabric, the general build loop, learning and proof of magic

## Decision

The corrected north star remains a user-owned conversational software foundry.
Iter must use the facilities we build to research, author, test, repair, revise,
recover and preserve requested apps. Codex develops the platform; Iter authors
the proof application's feature code. A platform fixture cannot satisfy that proof.

Delivery is one connected workflow. Named cognitive spaces, native engineering
governance and cumulative learning are mandatory platform behavior, including
when a resulting app has no domain-reasoning feature. An app's use of domain
cognition remains optional; the builder's use of governance and learning does not.

1. Keep control, personal, learning, project and scratch identities behind one
   fabric contract. Use the existing journal first, with per-space permissions,
   exact SnapshotSets, replay and a replaceable physical routing boundary.
2. Provide generic app projects and typed build actions. Iter turns a conversation
   into intention, invariants, current state, gap, alternatives, predictions,
   test/recovery obligations and bounded authorization.
3. Native reasoning selects or evaluates the next bounded action. The external
   executor verifies scope and snapshot, executes it, and records raw observations.
   Native reasoning compares outcomes and chooses accept, iterate, escalate or
   rollback. The same work shape is used for features and repairs.
4. Every completed action has a unique evidence identity. PLN/NACE revision
   accumulates evidence without duplicate counting. A later work unit must show
   that evidence changed candidate ranking or a proof obligation.
5. Through chat, Iter builds an unprepared app, demonstrates its real workflow,
   preserves its data through restart, makes a requested revision, and recovers
   the exact healthy version from a failed candidate. The trace links all steps
   to the named spaces, native decisions and evidence above.
6. A second materially different app tests generality through the same interfaces.

COG-LEARN-1 is required in this integrated acceptance, not deferred to a later
research project. COG-GOV-1's historical completion covers one fixed action only;
it does not certify a general build loop. BUILD-LOOP-1 closes that gap.

## Isolated development and adoption

Use a fresh source snapshot that includes the current uncommitted work. Exclude
live state, private files, credentials, caches, generated dashboards and dependencies.
Record a baseline hash for every source file. Develop and test supporting platform
code in that workspace, using injected adapters and temporary state. Native rules
may be tested with a disposable Hyperon engine; this never copies the live AtomSpace.

Before adoption, produce a reviewable patch and compare each touched live file
against its baseline. A mismatch requires merging the actual new source; never
overwrite concurrent edits. Integrate the verified patch into the current checkout,
then perform the live lifecycle and Iter-authored acceptance that isolation cannot
establish. Use the existing candidate authorization/recovery boundary for activation.
Preparatory isolated source work does not require another PWQ signature. Do not
fabricate a human signature or reuse the obsolete factory-only card as authority
for the expanded integrated runtime change.

## Commitments retained

Spec Kit process grammar; mini-SWE action/observation discipline; Agentless repair
stages; Aider repository context/feedback; Plandex isolation/rewind; an audited
v08.7.2 algebra subset; and Hyperon PLN/NACE evidence revision remain traceable
design commitments. A reference is not counted as implemented merely because
its name appears in documentation. Cite the actual adopted behavior and proof.

CSV contact import, Mattermost-derived useful briefs, later Calendar/Gmail
integration, user-owned source/data and the one-command Mac installer remain
recorded product commitments. The integrated toolmaking demonstration establishes
the foundation they use; it does not cancel them or imply their completion.

## Acceptance and nonclaims

Contract v2 adds BC-11 named fabric, BC-12 general native build loop, and BC-13
cumulative learning. BC-01 through BC-08 and BC-11 through BC-13 must share a
real Iter-authored build/revision trace before the integrated proof passes.
BC-09 adds application domain cognition when requested. BC-10 proves generality.
Passing isolated component tests is progress toward these clauses, not completion.
The production AtomSpace, independent supervisor and visible app round trip are
tested in the real environment after adoption. No claim of unrestricted arbitrary
software, perfect future builds or recovery from every possible failure is made.
