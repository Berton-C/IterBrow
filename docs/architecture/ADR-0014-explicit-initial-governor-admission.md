# ADR-0014: Explicit initial governor admission and stopped-source handoff

- Status: implemented in isolation; initial live admission not yet performed
- Date: 2026-09-22
- Atlas: GOV-SELF-1, INV-39, LIFE-1, REC-1
- Authority: the accepted thin constitutional kernel/native-governor boundary and
  the user's permission to integrate tested source and approve build-scoped PWQ
  cards while absent. This document is not itself a signature or deployment receipt.

## Initial trust is not a native successor decision

The previous governor does not contain the new general governor-change rule.
Allowing the candidate to approve itself would manufacture native authority.
The first new-foundry trust root therefore uses one explicit, separately scoped
human initialization, with distinct human-owner and runtime-guardian attestations.
Its PWQ scope binds the exact complete protected-source manifest, native seed
hashes, current control SnapshotSet and independently observed source/test/recovery
bundle. The guardian signs that exact observation bundle, not a generic success flag.

The canonical journal records a tagged `human_bootstrap_v1` receipt, explicitly
stating that no native successor decision or four-proof successor evaluation was
performed. A permanent once-only admission marker prevents initialization from
becoming a fallback whenever later native deliberation rejects or cannot run.
Subsequent changes use the approved parent's native rules plus separate PWQ scope,
shadow comparison, counterexamples, restart and rollback observations. Python
authenticates identities and executes source replacement; it does not select the
semantic conclusion. Missing real observer recipes remain missing, not default passes.

## Source recovery does not roll back mind

The host stops the supervised Iter child, then its Electron lifecycle owner,
then quiesces/checkpoints/stops the detached AtomSpace service. Electron's watchdog
must not be left able to respawn the service during this procedure. The host then
takes the existing state-owned service lock before opening the existing journal.
It refuses missing authority, symlinks, a second owner or an unconfirmed lifecycle.

Source artifacts retain exact before/after bytes and modes. Installation rejects
concurrent edits, journals progress and can restore a partially installed bundle.
The connected host entry point rechecks authorization and control identity before
source mutation, atomically records governance adoption after exact installed-byte
verification, and restores the retained parent if adoption fails. Recovery never
copies an older journal, clears memory, erases failed-build evidence or creates a
replacement epoch. Restoring source and reconciling its activation receipt are
separate observable steps so interruption between them can be recovered.

This is not an OS sandbox or a guarantee against arbitrary same-user shell writes.
Existing local reset/shutdown endpoints and human archive import remain host-trust
boundaries. The new foundry guard may pause on drift without disabling ordinary
Iter tools, semantic/episodic memory or the original hot-load recovery lane.

## Acceptance and remaining obligations

Initial release checks distinguish source-only temporary recovery with synthetic
memory from actual live restart/memory continuity. Both are reported truthfully;
the former cannot close the latter. The running service must actually reload its
source, and the new Iter tool must enter the active managed generation; merely
restarting Electron establishes neither fact.

The external Contract-v2 verifier retains all thirteen clauses and distinguishes
fixture, rehearsal, declaration and independent observation. A mechanically
assigned `actor=iter` is not proof of Iter authorship. Live tool-call/transcript
attribution and the human's unprepared request remain required. First-app proof,
material revision, learned improvement, second-category proof, CRM value and Mac
installation commitments remain open until their own evidence exists.
